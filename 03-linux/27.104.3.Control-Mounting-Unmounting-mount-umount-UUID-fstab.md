# LPIC-104.3 — Dosya Sistemlerini Bağlama ve Ayırma (mount / umount)

## Konu
Ağırlık **3**. Dosya sistemlerini **bağlama** (*mounting*) ve **ayırma** (*unmounting*): mount points, `mount` / `umount`, UUID, `/etc/fstab`, `blkid` / `lsblk`, systemd `.mount` farkındalığı.

**İki bölüm (tek oturum özeti):**
1. **104.3 · 1/2** — Tek hiyerarşi, mount point, elle bağlama/ayırma, `-t` / `-o`
2. **104.3 · 2/2** — UUID, etiketler, fstab sütunları, boot’ta otomatik bağlama

**Hedef:** Elle güvenle `mount`/`umount` yapmak, UUID ile kalıcı tanımlamak, `/etc/fstab` ile boot’ta otomatik bağlamak.

**Senaryo:** Yeni disk / USB / log dolması → `/var/log` için ayrı disk bağla; boot sonrası da aynı noktaya gelsin.

---

## Mount Nedir? (Windows’tan fark)
- Windows: yeni disk → `C:`, `D:`, `E:` gibi sürücü harfi.
- Linux/Unix: **tek hiyerarşi** — kök `/`; altında `/etc`, `/home`, `/proc`, …
- Fiziksel/ağ depolama bu ağaca **otomatik dahil olmaz**; bir **mount point** dizinine bağlanır.
- Günümüzde sık yer: `/media/...` · klasik: `/mnt/...`

```text
/dev/sdb1  →  mount  →  /media/new_disk
```

Bağladıktan sonra o dizindeki içerik, bağlı dosya sisteminin içeriğidir; mount point’te önceden duran dosyalar **gizlenir**, `umount` sonrası geri görünür.

---

## Pratik akış (VirtualBox + Ubuntu örneği)

### 1) Diski gör
```bash
lsblk
# sda (OS), sdb (yeni, MOUNTPOINTS boş) …
```

### 2) Bölüm + dosya sistemi (önceki konulardan hatırlatma)
```bash
sudo fdisk /dev/sdb    # n → primary → Enter… → w
sudo mkfs.ext4 /dev/sdb1
```

| Araç | Rol |
|---|---|
| `fdisk /dev/sdb` | Bölüm yönetimi (interaktif: `n`, `w`) |
| `mkfs.ext4 /dev/sdb1` | ext4 dosya sistemi oluştur |

### 3) Mount point + bağla
```bash
sudo mkdir /media/new_disk
sudo touch /media/new_disk/main_file   # mount öncesi “gizli kalacak” örnek
sudo mount /dev/sdb1 /media/new_disk
cd /media/new_disk && ls               # main_file yok; lost+found görünür
```

`lost+found` → fsck sonrası kurtarılan parçaların tutulduğu dizin (ext*).

### 4) Bağlı sistemleri listele
```bash
mount
# /dev/sdb1 on /media/new_disk type ext4 (rw,relatime)
# /dev/sda2 on / type ext4 (...)
```

### 5) Ayır
```bash
sudo umount /dev/sdb1
# veya
sudo umount /media/new_disk
ls /media/new_disk   # main_file geri gelir
```

## Neden ayrı bölümlere bağlarız?
Örnek kurulum:
- `/` → OS
- `/home` → kullanıcı verisi
- `/var/log` → log’lar (dolunca 2 TB disk alıp buraya bağla)

Avantaj: log diskini `umount` edip fiziksel/sanal olarak söküp başka makinede inceleyebilirsin; kök sistemi etkilemez.

## `mount` seçenekleri: `-t` ve `-o`

```bash
sudo mount -t ext4 /dev/sdb1 /media/new_disk
sudo mount -o rw,user /dev/sdb1 /media/new_disk
sudo mount -o loop dosya.iso /media/mount_point   # ISO bağlama
```

| Seçenek | Anlamı |
|---|---|
| `-t ext4` | Türü açıkça söyle (yoksa tahmin eder) |
| `-o defaults` | Varsayılanlar |
| `-o rw` / `ro` | Okuma-yazma / salt okunur |
| `-o user` | Kullanıcı bağlayabilir (root şart değil) |
| `-o noauto` | Boot’ta otomatik bağlama |
| `-o exec` / `noexec` | Çalıştırılabilir / değil |
| `-o noatime` | Erişim zamanı güncellemesini kapat |
| `-o loop` | Dosyayı (ISO) blok gibi bağla |

**Not:** Swap için `mount` kullanılmaz → `swapon` / `swapoff` (ayrı konu).

## Cihaz adları güvenilmez → Label → UUID

`/dev/sdb1` bağlantı sırasına / makineye göre değişebilir (`sdc1`, `sdd1`…). Script’lerde risk.

| Yöntem | Sorun / avantaj |
|---|---|
| Cihaz adı (`/dev/sdb1`) | Dinamik, değişebilir |
| **Label** (örn. `backup`) | Okunaklı ama çakışabilir (herkes “backup” der) |
| **UUID** | Formatta atanan sabit, benzersiz kimlik |

```bash
lsblk -o NAME,UUID
lsblk -O          # tüm sütunlar
blkid
blkid /dev/sdb1
```

UUID ile bağlama:
```bash
sudo umount /media/new_disk
sudo blkid /dev/sdb1
sudo mount UUID=<uuid> /media/new_disk
mount | grep sdb1
```

---

## `umount`: “target is busy”

Bağlı dizinin **içindeyken** ayıramazsın → önce `cd` ile çık.

| Bayrak | Anlamı |
|---|---|
| `umount -f` | Zorla (özellikle erişilemeyen NFS) |
| `umount -l` | **Lazy**: hiyerarşiden hemen ayır; meşgul bitince referansları temizle |

```bash
sudo umount -l /media/new_disk
```

---

## `/etc/fstab` — boot’ta otomatik bağlama

Elle `mount`/`umount` geçici. Kalıcı yapılandırma: **File Systems Table**.

Sütunlar (tab/boşluk ayrımı; tab daha okunaklı):

| # | Alan | Örnek | Anlamı |
|---|---|---|---|
| 1 | Dosya sistemi | `UUID=...` veya `/dev/sdb1` | Ne bağlanacak |
| 2 | Mount point | `/media/new_disk` | Nereye |
| 3 | Tür | `ext4` | FS tipi |
| 4 | Seçenekler | `defaults`, `rw`, `noauto`, `user`… | Nasıl |
| 5 | dump | `0` / `1` | Yedeklemeye dahil mi |
| 6 | pass | `0` / `1` / `2` | Boot’ta `fsck` sırası (`/` genelde `1`) |

Örnek satır fikri:
```text
UUID=xxxx-....    /media/new_disk    ext4    rw    0    2
```

`vi /etc/fstab` ile düzenle.

**Fayda:**
- Reboot sonrası otomatik bağlanır.
- `mount /dev/sdb1` (veya UUID) yazınca fstab’daki hedefe **kısa yoldan** bağlanır; mount point tekrar yazmana gerek kalmaz.

---

## systemd farkındalığı (LPIC-1)
- `.mount` birimleri de bağlama bilgisi taşır; systemd bunlarla mount yapabilir.
- Sınav seviyesinde: **varlığını bilmek** yeterli (init’in ötesinde rol üstlenmesi tartışması notu).

## Pratik tavsiye
VM’ye yeni disk ekle → `lsblk` → `fdisk` → `mkfs` → `mount` / `umount` → UUID → `/etc/fstab` → reboot ile doğrula.

---

## Özet
- Linux’ta tek ağaç; diskler **mount point**’e bağlanır
- `mount` / `umount` · `mount -t` · `-o rw|ro|user|loop|…`
- Cihaz adı değişebilir → **UUID** (`blkid`, `lsblk -o UUID`)
- Kalıcı: **`/etc/fstab`** (6 sütun; dump / pass)
- Busy → dizinden çık veya `umount -l`
- 104.4 quotas → LPIC-1 5.0’da yok
