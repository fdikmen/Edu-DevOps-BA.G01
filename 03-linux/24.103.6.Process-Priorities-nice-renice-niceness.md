# LPIC-103.6 — Process Öncelikleri (nice, renice, niceness)

## Konu
Ağırlık **2**. Çalışan process'lerin **CPU önceliğini** kontrol etmek: `nice` (başlatırken), `renice` (çalışırken), `ps -l` / `top` ile gözlem.

**Senaryo:** Gece 03:00 yedekleme tüm kaynakları yiyor → görevi durdurmak yerine **niceness yükselt** (daha nazik yap); diğer isteklere kaynak kalır.

---

## Niceness Ölçeği
`NI` sütunu (`top`, `ps -l`): **-20 … 19**

| Değer | Anlamı |
|---|---|
| **-20** | En agresif — en yüksek öncelik (kaynak ister) |
| **0** | Varsayılan (çoğu kullanıcı komutu) |
| **19** | En nazik — en düşük öncelik (diğerlerine yer bırakır) |

Mantık: niceness **yüksek** → daha kibar → daha az kaynak. Niceness **düşük/negatif** → açgözlü → OS öncelik verir. Önemli sistem process'leri genelde düşük (agresif) NI ile çalışır.

---

## nice — Başlatırken Öncelik Ayarla
```bash
nice                    # mevcut varsayılanı göster → genelde 0
nice ls                 # parametresiz → NI = 10
nice -n 15 ls           # NI = 15
nice -n -10 ls          # normal kullanıcı → permission denied (komut yine 0 ile çalışır)
```

| Çalıştırma | Niceness |
|---|---|
| `komut` | 0 |
| `nice komut` | 10 |
| `nice -n N komut` | N |

**Kural:** Negatif niceness (öncelik artırma) yalnızca **root**. Aksi halde herkes -20 isterdi.

Yoğun işler için örnek: `nice gzip büyük_dosya` — birkaç dakika uzayabilir, diğer kullanıcıları boğmaz.

---

## ps -l ile Niceness Görmek
```bash
nice xeyes &
ps -l                   # long format → NI sütunu (örn. xeyes = 10)
```
`PRI` (priority) ayrı bir alan; niceness onu dolaylı etkiler. Odak: `nice` / `NI`.

---

## Process Durum Kodları
`man ps` — STAT sütunu:

| Kod | Anlamı |
|---|---|
| `R` | Running — çalışıyor |
| `S` | Sleep (interruptible) — olay bekliyor (örn. xeyes fare hareketi) |
| `T` | Job control ile durdurulmuş (`Ctrl+Z`) |
| `t` | Debugger ile durdurulmuş |
| `I` | Idle kernel thread |
| `D` | Uninterruptible sleep — genelde I/O |
| `W` | Paging — bellek sayfalama |
| `X` | Dead — pratikte görülmez |
| `Z` | Zombie |

### Zombi (`Z`)
Child işini bitirdi, dönüş değerini parent henüz okumadı → process “ölü ama tabloda duruyor”.

- CPU/RAM tüketmez; sadece process tablosunda satır kaplar.
- Zararsızdır; kötü yönetilen parent’ı işaret eder.
- Binlerce birikirse tablo dolar → parent’ı yeniden başlat / sonlandır.

## renice — Çalışan Process'in Önceliğini Değiştir
```bash
renice -n 15 7968              # PID 7968 → NI 15
ps -l                          # doğrula
pgrep eyes | xargs renice -n 10   # isimde "eyes" geçenlerin hepsini NI=10 yap
```

**top içinde:** `r` → PID sor → yeni niceness gir.

### renice kuralları
- Niceness’ı **yukarı** (daha nazik, örn. -20 → -10 veya 10 → 15) her zaman yükseltebilirsin.
- **Sıfırın altına** (daha agresif) indirmek → **root** gerekir.

---

## Özet
- Ölçek: **-20 (agresif) … 0 (varsayılan) … 19 (nazik)**
- `nice` / `nice -n N` → başlatırken; `renice -n N PID` → çalışırken
- Negatif NI → root; `ps -l` / `top` (`NI`, `r`) ile izle/değiştir
- Durumlar: `R S T D Z`…; zombi genelde zararsız
- Pratik: yedekleme, büyük `gzip`/FTP → `nice` ile diğer işlere yer bırak
