# LPIC-103.4 / 103.5 — Streams, Redirects, Pipe'lar ve Process Yönetimi Temelleri

## Konu
Ağırlık **4**. Bu bölümde: standart akışlar (`stdin`/`stdout`/`stderr`), yönlendirme, pipe, `xargs`, `tee`; ardından Process yönetimi: `jobs`, `fg`/`bg`, `&`, `nohup`, `kill` / `killall` / `pkill`.

> **Not:** zsh'de bazı yönlendirmeler farklı davranabilir; bu konuyu çalışırken `bash` kullanmak daha güvenli.

---

## Üç Standart Akış

| FD | Akış | Varsayılan kaynak/hedef |
|---|---|---|
| `0` | `stdin` (standart girdi) | Klavye |
| `1` | `stdout` (standart çıktı) | Terminal ekranı |
| `2` | `stderr` (standart hata) | Terminal ekranı |

- Normal sonuç → `stdout`; hata → `stderr` (ikisi de ekranda görünür, kanal farklıdır).
- Örn. `ls j*` → eşleşme varsa stdout; `ls x*` eşleşme yoksa stderr.

## Yönlendirme (Redirect)

### stdout: `>` ve `>>`
```bash
ls > list_of_files      # üzerine yaz (overwrite); dosya varsa silinir
tree >> list_of_files   # sonuna ekle (append) — log için ideal
```
`>` ≡ `1>` · `>>` ≡ `1>>`

### stderr: `2>` ve `2>>`
```bash
ls x* 2> errors
ls x* 2>> errors
```

### stdout + stderr birlikte
```bash
ls x* j* > my_files 2> ls_errors   # ayrı dosyalara
ls x* j* > my_files 2>&1           # stderr → stdout'un gittiği yer
ls x* j* &> my_files               # kısayol (aynı)
ls x* j* &>> my_files              # ikisini sonuna ekle
```
**Yanlış:** `> file 2> file` — iki ayrı açılış çakışabilir. **Doğru:** `> file 2>&1` veya `&> file`.

### stdin: `<`
```bash
echo "Merhaba Linux" > input.txt
cat < input.txt                    # dosya → stdin → cat
cat < input.txt > output.txt       # girdi + çıktı birlikte
```

## `/dev/null` ve Here Docs

**`/dev/null`** — buraya yazılan her şey yok sayılır (black hole).
```bash
ls olmayan_dosya 2> /dev/null
ls j* x* > dosya 2> /dev/null      # çıktıyı kaydet, hataları yut
```

**Here doc** — dosya oluşturmadan çok satırlı girdi:
```bash
cat << SON > mesaj.txt
Linux öğreniyorum.
Here Doc kullanıyorum.
SON

tr a-z A-Z << EOF
linux terminal
EOF
```
`SON` / `EOF` sadece delimiter; teknik fark yok.

## Pipe (`|`)
Bir komutun **stdout**'unu diğerinin **stdin**'ine bağlar (Unix Lego'su).

```bash
ls -1 | wc -l
cut -d' ' -f2 login.txt | sed 's/ //g' | sort | uniq -c | sort -nr
```

| Adım | Rol |
|---|---|
| `cut` | Alanı ayıkla |
| `sed 's/ //g'` | Boşlukları sil |
| `sort` | `uniq` için sırala |
| `uniq -c` | Tekrarları say |
| `sort -nr` | Sayısal, büyükten küçüğe |

Bazı komutlar dosya da alır (`wc -l dosya`); bazıları sadece stdin ister → pipe gerekir.

## xargs
Stdin'deki değerleri başka komuta **argüman** olarak ekler (boşluk/tab/newline ile ayırır).

```bash
cat files | xargs echo                         # → echo file1.txt file2.txt ...
printf "one\ntwo\nthree\n" | xargs echo        # → one two three
ls *.log | xargs -I {} mv {} /tmp/backup/{}       # {} yer tutucu (-I)
printf "one\ntwo\nthree\nfour\n" | xargs -n 2 echo   # her seferde 2 arg
ls *.log | xargs -n 1 -I {} cp {} /tmp/backup/
```

| Seçenek | Anlamı |
|---|---|
| `-I {}` | `{}` yer tutucusu ile konum seç |
| `-n N` | Her çalıştırmada N argüman |

## tee
Pipe üzerinden gelen veriyi **hem ekrana hem dosyaya** yazar.

```bash
ls | tee files.txt                 # üzerine yaz + ekrana göster
ls | tee first.txt second.txt      # birden fazla dosya
ls | tee -a files.txt              # append
command 2>&1 | tee output.txt      # stderr'i de dahil et
```

## Process Yönetimi Temelleri

### Ctrl+C / Ctrl+Z / jobs
| Kısayol | Etki |
|---|---|
| `Ctrl+C` | Process i sonlandır (terminate) |
| `Ctrl+Z` | Durdur / askıya al (Stopped) — öldürmez |

```bash
jobs          # bu shell'deki işler
# [1]+ Stopped  xeyes
# + = current job, - = previous job
```

### fg / bg / `&`
```bash
fg %1         # 1 numaralı işi ön plana al (terminal kilitlenir)
fg            # + işaretli varsayılan iş
bg %1         # durdurulmuş işi arka planda devam ettir
xeyes &       # doğrudan arka planda başlat → [1] 4821 (job + PID)
```
`&` ile başlasa bile Process **terminal oturumuna bağlıdır**; SSH kapanınca genelde ölür.

### nohup — hangup'a dayanıklı
```bash
nohup long_task.sh &
nohup tar cf backup.tar /home &
cat nohup.out
tail -f nohup.out     # canlı takip
```
SIGHUP'ı yok sayar; çıktı varsayılan olarak `nohup.out`'a gider. `jobs` ile görünmeyebilir (oturumdan kopuk).

### PID ve kill
```bash
jobs -l               # job number + PID
kill 2456             # varsayılan: TERM (15) — düzgün kapan
kill -9 2456          # KILL — zorla (yakalanamaz)
kill -1 2456          # HUP
sudo kill -9 2456     # başka kullanıcıya ait Process
```

| Sinyal | No | Anlamı |
|---|---|---|
| `TERM` | 15 | Düzgün kapan (ilk tercih) |
| `KILL` | 9 | Zorla sonlandır |
| `HUP` | 1 | Bağlantı kesildi (`nohup` bunu yoksayar) |

### İsme göre: killall / pkill
```bash
killall python        # tam isim eşleşmesi + TERM
killall -9 python
pkill -9 eyes         # regex — adında "eyes" geçenler (dikkat!)
pkill calc
```
`killall` daha kesin; `pkill` daha esnek, yanlış eşleşme riski yüksek.

## Özet
- Akışlar: `0` stdin · `1` stdout · `2` stderr
- Yönlendirme: `>`/`>>`, `2>`, `2>&1` / `&>`, `<`; çöp kutusu: `/dev/null`; çok satır: `<< EOF`
- Pipe zinciri + `xargs` (-i, -n) + `tee` (-a)
- Process: `Ctrl+Z` → `jobs` → `fg`/`bg`; `&` / `nohup … &`; `kill`/`killall`/`pkill`
