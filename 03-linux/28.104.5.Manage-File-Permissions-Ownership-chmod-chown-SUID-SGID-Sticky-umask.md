# LPIC-104.5 — Dosya İzinleri ve Sahiplik (Permissions & Ownership)

## Konu
Ağırlık **3**. Dosya güvenliğinin temeli: kullanıcılar / gruplar, `ls -l`, `chmod`, `chown` / `chgrp`, paylaşımlı klasörler, **SUID** / **SGID** / **Sticky Bit**, `umask`.

**Üç soru (sürekli sor):**
1. Bu işlemi **kim** yapıyor?
2. Dosyanın **owner** ve **group**’u kim?
3. Bu kullanıcı için hangi **izinler** tanımlı?

**Senaryo:** `developers` ekibi `/srv/project` altında ortak çalışacak → grup, `chmod 2770`, SGID, `umask` birlikte.

---

## User, Group, Other
| Kategori | Kim |
|---|---|
| **owner** (u) | Dosyanın sahibi |
| **group** (g) | Dosya grubunun üyeleri |
| **other** (o) | Geri kalan herkes |

Çoğu distroda yeni kullanıcıyla aynı isimde **primary group** oluşur (`fd` → grup `fd`). Kullanıcı ayrıca `sudo`, `adm`, … gibi **supplementary** gruplarda olabilir.

```bash
whoami
groups
id          # uid=… gid=… groups=… (primary + supplementary)
sudo su     # root → UID 0
```

Linux isimleri insanlar için; sistem **UID** / **GID** kullanır. **UID 0** = root.

### Hesap dosyaları (kısa)
| Dosya | İçerik |
|---|---|
| `/etc/passwd` | kullanıcı, UID, primary GID, home, shell (`x` → parola shadow’da) |
| `/etc/shadow` | parola hash’leri (`sudo cat`) |
| `/etc/group` | grup adı, GID, üyeler |

## `ls -l` okumak

```bash
ls -l
# -rwxr-xr-- 1 firat firat …
# │└─┬─┘└─┬─┘└─┬─┘
# │  u    g    o
# └── tür (- dosya, d dizin, l symlink, …)
```

```text
-rw-rw-r--
│ │ │ └── other → r--
│ │ └──── group → rw-
│ └─────── owner → rw-
└───────── regular file
```

Owner ve group sütunları olmadan yalnızca `rwx` yetmez.

### `r` `w` `x` — dosya vs dizin

| Bit | Dosya | Dizin |
|---|---|---|
| **r** | İçeriği oku | İçeriği **listele** |
| **w** | İçeriği değiştir | İçerde oluştur / sil / yeniden adlandır |
| **x** | Çalıştır | **Traverse** — dizine gir / yol üzerinde ilerle |

Dizinde `x` ≠ “program çalıştır”; erişim / geçiş iznidir.

Örnekler:
```bash
touch ~/permission-example.txt
ls -l ~/permission-example.txt    # örn. -rw-rw-r--
ls -l /usr/bin/ls                 # l… → symlink olabilir
ls -ld /home                      # d… → directory
```

## `chmod` — oktal

| Bit | Değer |
|---|---|
| r | 4 |
| w | 2 |
| x | 1 |

Topla: `rwx`=7, `rw-`=6, `r-x`=5, `r--`=4.

| Değer | Anlamı |
|---|---|
| `600` | owner rw; g/o yok |
| `644` | owner rw; g/o r |
| `640` | owner rw; group r |
| `700` | yalnız owner rwx |
| `750` | owner rwx; group r-x |
| `755` | owner rwx; g/o r-x → `rwxr-xr-x` |
| `770` | owner+group rwx |
| `775` | owner+group rwx; other r-x |
| `777` | herkese rwx — **alışkanlık yapma** |

```bash
chmod 755 directory
chmod -R 755 directory    # recursive — güçlü ve tehlikeli; path’i iki kez kontrol et
# chmod -R 777 … → kaçın
```

---

## `chmod` — sembolik

| Harf | Kim |
|---|---|
| `u` | owner |
| `g` | group |
| `o` | other |
| `a` | all (u+g+o) |

| Operatör | Etki |
|---|---|
| `+` | ekle |
| `-` | kaldır |
| `=` | doğrudan ata |

```bash
chmod u+x script.sh
chmod g+w file
chmod o-r file
chmod u=rwx,g=rw,o= file
```

## `chown` ve `chgrp`

```bash
touch my_file
ls -l my_file                         # firat firat
sudo adduser tommy
sudo chown tommy my_file              # owner → tommy; group aynı kalabilir
sudo groupadd developers
sudo chgrp developers my_file         # yalnız group
sudo chown firat:developers my_file   # owner:group birlikte
getent group
```

| Komut | Ne yapar |
|---|---|
| `chmod` | izinler — “kim ne yapabilir?” |
| `chown` | owner (+ gerekirse group) |
| `chgrp` | yalnız group |

**Yetki:** Kendi dosyanın izinlerini değiştirebilirsin. Başkasının **ownership**’ini almak normal kullanıcıya yasaktır → genelde **root** / `sudo`.

Temizlik örnekleri: `sudo deluser tommy` · `sudo deluser --remove-home tommy` · `sudo groupdel developers`

## Gruplar ve paylaşımlı klasör

```bash
sudo usermod -aG sudo tommy       # -a şart: yoksa mevcut supplementary gruplar silinebilir
# yeni login veya:
newgrp sudo                       # shell’in etkin grubunu değiştir (kalıcı primary değil)
newgrp lxd
touch new_file                    # group → etkin grup
# kalıcı primary: usermod -g …
```

Paylaşımlı klasör iskeleti:
```bash
sudo groupadd developers
mkdir sharedFolder
sudo chgrp developers sharedFolder
chmod g+rwx sharedFolder
sudo usermod -aG developers tommy
```

Yeni dosyaların group’unun tutarlı kalması için → **SGID** (aşağıda).

## Special bits: SUID, SGID, Sticky

| Bit | Oktal | `ls` göstergesi | Özet |
|---|---|---|---|
| **SUID** | `4000` | owner `x` yerine `s` (`-rws…`) | Çalışırken **effective UID** ≈ dosya owner |
| **SGID** | `2000` | group `s` | Executable: effective GID ≈ dosya group · **Dizin:** yeni içerik parent group miras alır |
| **Sticky** | `1000` | other sonunda `t` (`…rwt`) | Yazılabilir dizinde sil/rename → çoğunlukla yalnız dosya sahibi / dizin sahibi / root |

```bash
# örnek birleşimler
4755   # SUID + 755
2770   # SGID + 770
1777   # sticky + 777

chmod u+s file      # SUID
chmod g+s file      # SGID
chmod +t directory  # sticky
chmod u-s file
chmod g-s file
chmod -t directory
```

### SUID — `passwd`
```bash
which passwd
ls -l /usr/bin/passwd    # -rwsr-xr-x → SUID
```
Sıradan kullanıcı `/etc/shadow`’a yazamaz; `passwd` SUID ile controlled privilege kullanır. SUID kullanıcıyı “genel root” yapmaz — effective UID dosya owner’ına bağlıdır. **SUID root** binary’ler güvenlik açısından kritik.

### Sticky — `/tmp`
```bash
ls -ld /tmp              # drwxrwxrwt
chmod +t directory
chmod 1777 directory
```

## `umask`

Yeni dosya/klasörde hangi bitlerin **maskeleneceği**. Mevcut dosyaları değiştirmez.

| | Temel | Örnek `umask 022` | Örnek `umask 077` |
|---|---|---|---|
| Dosya | `666` | `644` (`rw-r--r--`) | `600` |
| Dizin | `777` | `755` (`rwxr-xr-x`) | `700` |

```bash
umask                 # gör
umask 066
touch umask_file
ls -l umask_file      # -rw-------
```

Shell oturumuna göre değişebilir; varsayımı ezberleme — önce `umask` ile bak.

## Shared Project Directory (birleşik senaryo)

```bash
sudo usermod -aG developers firat
sudo mkdir /srv/project
sudo chgrp developers /srv/project
sudo chmod 2770 /srv/project          # 2=SGID + 770

touch /srv/project/test.txt
ls -l /srv/project/test.txt           # group ≈ developers (SGID mirası)
# umask 002 → dosya ≈ 664 (rw-rw-r--)
```

Üç mekanizma birlikte: klasör owner/group · SGID mirası · kullanıcının `umask`’ı.

## Özet
- Model: **owner · group · other** + UID/GID; root = UID 0
- `ls -l` oku; dizinlerde `x` = traverse
- `chmod` oktal/sembolik · `-R` dikkatli · `777` alışkanlık değil
- `chown` / `chgrp` — ownership ayrıcalıklı
- Gruplar: `usermod -aG`, `newgrp`, paylaşımlı dizin
- Special: SUID `4000` · SGID `2000` · sticky `1000`
- `umask`: dosya 666 / dizin 777 üzerinden maske
