# LPIC-102.6 — Linux as a Virtualization Guest (VM, Hypervisor, Containers, IaaS)

## Konu
Linux'u **guest** (misafir) sistem olarak ele almak: sanal makineler, hipervizörler, konteynerler ve IaaS. Sonraki derslerde pratik komut satırına geçilir.

| Terim | Anlamı |
|---|---|
| **Host** | Fiziksel makine / sanallaştırmayı sağlayan ana OS |
| **Guest** | Host üzerinde çalışan sanal OS |
| **Hipervizör** | Bilgisayarı emüle eden yazılım (VM yöneticisi) |

Sık geçenler: sanal makine, Linux/uygulama konteyneri, sürücüler, SSH host anahtarları, D-Bus, machine ID.

---

## Sanal Makine ve Sanal Donanım
VM fiziksel değildir; hipervizör (örn. VirtualBox) donanımı simüle eder.

| Bileşen | Gerçekte ne olur? |
|---|---|
| Sanal CPU | Fiziksel CPU'da, hipervizör denetiminde çalışır |
| Sanal RAM | Fiziksel RAM'e yazılır |
| Sanal disk | Host diskte bir **dosya**dır |

Bir hipervizörde birden fazla VM olabilir (GUI penceresi zorunlu değil).

---

## Sanallaştırma Desteğini Kontrol Etmek

| Bayrak / işaret | Anlamı |
|---|---|
| `vmx` | Intel VT-x |
| `svm` | AMD-V |
| `hypervisor` (`/proc/cpuinfo`) | Zaten bir VM içindesin (fiziksel değil) |

Bazen BIOS/UEFI'de sanallaştırma kapalıdır → elle açmak gerekir.

```bash
grep -E 'vmx|svm' /proc/cpuinfo    # donanım desteği
lscpu | grep Virtualization         # VT-x / AMD-V özeti
lsmod | grep kvm                    # KVM yüklü mü? (kvm_intel / kvm_amd)
# ayrıca: /dev/kvm erişimi
```

### Platform özeti
| Platform | Nasıl doğrula? |
|---|---|
| Linux (Intel/AMD) | `vmx`/`svm`, `lscpu`, `lsmod kvm`, `/dev/kvm` |
| Windows | Görev Yöneticisi → Performans → Sanallaştırma; veya `systeminfo` (Hyper-V) |
| Apple Silicon (ARM64) | EL2 her zaman aktif (BIOS'tan kapatılmaz); `sysctl kern.hv_support` → `1` |
| Apple Silicon üzerinde Linux VM | `/dev/kvm`; ARM'de `vmx`/`svm` bayrağı yok |

## Hipervizör Türleri

### Tip 2 — Hosted
Donanım → Host OS (örn. Windows) → Hipervizör (VirtualBox, VMware) → Guest VM'ler.

### Tip 1 — Bare metal / native
Hipervizör doğrudan donanımda çalışır; guest'ler onun üzerine kurulur.

| Tip | Örnekler |
|---|---|
| Tip 2 | VirtualBox, VMware |
| Tip 1 | KVM (Linux kernel ≥ 2.6), Xen, Hyper-V |

Pratikte büyük ortamlarda Tip 2 (VMware vb.) sık görülür.

---

## VM Oluşturma Yöntemleri
1. **Temel kurulum** — yeni VM + ISO/CD/DVD ile kur
2. **Klonlama** — aynı yapıda birden fazla makine; kaynak VM **kapalı** olmalı
3. **OVF / OVA** — dışa/içe aktarma (`OVF` = Open Virtualization Format; `OVA` = hepsinin tek arşivi)
4. **Template** — hazır şablon; klona benzer ama daha düzenli / yapılandırılabilir

### Klon / template sonrası dikkat
Aynı ağda çakışma riski. Ağa bağlamadan önce değiştir:

| Öğe | Neden |
|---|---|
| Hostname | Kimlik çakışması |
| NIC MAC | Aynı MAC olamaz |
| IP (DHCP yoksa) | Adres çakışması |
| Machine ID (D-Bus) | Benzersiz UUID gerekir |
| `~/.ssh` anahtarları | Yeniden üret |
| Disk UUID / şablon yer tutucuları | Dokümantasyona göre güncelle |

```bash
# benzersiz machine ID
rm /etc/machine-id /var/lib/dbus/machine-id
dbus-uuidgen --ensure
```

### Guest Additions / sürücüler
- **VirtualBox:** Devices → Install Guest Additions CD Image (grafik, tam ekran vb.)
- **VMware:** host araçları + guest ajan → düzgün kapatma, istatistik, izleme

## Konteynerler vs VM

| | Sanal makine | Konteyner |
|---|---|---|
| Katman | Hipervizör + tam guest OS | Host OS + konteyner motoru |
| Yük | Ağır (tam OS) | Hafif (binary + kütüphaneler) |
| İzolasyon | Guest OS sınırında | Konteyner izolasyonu; çökme host/diğerlerini etkilemez |

Avantajlar: sadece ihtiyaç duyulanı taşı; ölçek için yeni örnek; host kütüphanelerinden bağımsız geliştirme; upgrade öncesi test.

---

## IaaS — Infrastructure as a Service
Bulut sağlayıcı güç, ağ, disk, DB vb. altyapıyı hizmet olarak sunar; fiziksel yeri bilmeden makine ister / taşırsın.

| Bileşen | Örnek kullanım |
|---|---|
| Blok depolama / NIC | Panelden ekle → makineye bağlanır |
| Load balancer | Trafiği sunucular arasında dağıt |
| Object storage | Dosya sakla → benzersiz ID ile geri al |
| Managed database | Yönetilen DB hizmeti |

**Sağlayıcılar:** AWS, Google Cloud Platform, Microsoft Azure.  
**cloud-init:** komut satırından yapılandırmalı bulut örneği başlatma (AWS, DigitalOcean, Azure…).

---

## Özet
- Host / guest / hipervizör; sanal CPU/RAM/disk
- Destek: `vmx`/`svm`, KVM, platforma göre araçlar
- Tip 1 (bare metal) vs Tip 2 (hosted)
- Kurulum, klon, OVF/OVA, template; klon sonrası MAC, hostname, machine ID
- Konteyner = hafif, host OS paylaşır
- IaaS = altyapı hizmet olarak (AWS, GCP, Azure, cloud-init)
