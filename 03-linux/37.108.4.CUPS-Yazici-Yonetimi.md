# LPIC-108.4 — CUPS ve yazıcı yönetimi

## Konu
LPIC Topic **108** — Essential System Services. Bu ders **108.4**: Linux’ta yazdırma sistemi.

| Kod | Konu | Ağırlık |
|---|---|:---:|
| **108.4** | Manage printers and printing | 2 |

Posta aktarımı [108.3](36.108.3.MTA-Temelleri.md) içinde kaldı. Burada yazdırma var.

Amaç, her yazıcı modelini sıfırdan sürücüyle kurmak değildir. Hedef, **CUPS** (*Common Unix Printing System*) mimarisini tanımak; yapılandırma, kuyruk, web arayüzü, legacy BSD araçları ve kuyruğa kabul / yazdırma ayrımını bilmektir.

Kapsam: kurulum ve servis, üç yönetim yolu, `/etc/cups`, erişim denetimi, `printers.conf` / PPD / loglar, port **631**, `lpadmin` ile yazıcı ekleme, `lpr` / `lpq` / `lprm` / `lpc`, `cupsaccept` / `cupsreject` / `cupsenable` / `cupsdisable`.

Sıra: CUPS nedir → kurulum ve akış → yönetim yolları → yapılandırma → yazıcı kaydı → CLI ve web ile ekleme → legacy araçlar → iki anahtar.

## CUPS nedir?

**CUPS**, neredeyse tüm Linux sistemlerinde yazdırmayı uçtan uca yöneten ortak Unix yazdırma sistemidir. Büyük bir pakettir; filtreler, sürücüler, fontlar ve ilgili bileşenler bir arada gelir.

Dört işlev:

| Başlık | Ne yapar |
|---|---|
| **Configure** | Yazıcıları ve politikaları tanımlar |
| **Queue** | İşleri kuyrukta tutar, sıraya koyar, yönetir |
| **Troubleshoot** | İşler, servis ve log üzerinden sorunu ayırır |
| **Legacy** | Klasik **BSD** (*Berkeley Software Distribution*) tarzı komutlarla uyumluluk sağlar |

CUPS yalnızca “yazıcıya dosya atan” bir komut değildir. Kullanıcı işi gönderir; CUPS kuyruğa alır ve uygun yazıcıya iletir.

Ayrıca **LPD** (*Line Printer Daemon*) döneminden gelen eski arayüzler, uyumluluk katmanı olarak hâlâ önemlidir.

---

## Kurulum ve servis

Debian / Ubuntu örneği:

```bash
sudo apt install cups
```

Kurulumdan sonra paket boyutu büyük olabilir (örnekte ~163 MB). Sebep: sürücüler, filtreler, fontlar ve ek özellikler.

CUPS sürekli çalışan bir **daemon**’dır. Ana süreç genelde `/usr/sbin/cupsd` şeklindedir.

```bash
systemctl status cups
journalctl -u cups
```

Akış:

```text
Kullanıcı → cupsd → spool / kuyruk → hedef yazıcı
```

**Spool**, işin yazıcıya gitmeden önce beklediği alandır. Yerel, ağ ve sanal yazıcılar aynı serviste buluşur.

## Yapılandırma: `/etc/cups`

Yapılandırma `/etc/cups` altındadır. En kritik dosya **`cupsd.conf`**: daemon ayarları.

Örnek satırlar:

| Ayar | Anlamı |
|---|---|
| `MaxLogSize 0` | Log rotasyonunu kapatır (0 = boyut limiti yok / döndürme kapalı) |
| `Listen localhost:631` | Yalnızca yerel makineden erişim |
| `Listen 0.0.0.0:631` | Tüm arayüzler; ağdaki diğer makineler de web UI’ye ulaşabilir |

Tüm satırlar ezberlenmez. Web arayüzünün dinlediği adres ve erişim kuralları bu dosyaya bağlıdır.

### Erişim denetimi

Yol tabanlı kontrol vardır:

| Yol | Tipik kısıt |
|---|---|
| `/` (kök) | Genelde herkese açık görünüm |
| `/admin`, `/admin/conf` | Sistem yetkisi / root veya ayrıcalıklı grup |

Yönetimi delege etmek için örneğin `printer-admins` grubu oluşturulur, kullanıcı eklenir, `cupsd.conf` bu grubu referans alır, CUPS yeniden başlatılır. `CUPS-Add-Modify-Printer` / `CUPS-Delete-Printer` gibi işlem sınırları da aynı mantıkla root’tan gruba taşınabilir.

## Yazıcı kaydı, PPD ve loglar

| Yol / Kavram | Rol |
|---|---|
| `/etc/cups/printers.conf` | Tanımlı yazıcıların kaydı (ad, konum, model, URL, paylaşım, iş kabulü) |
| **PPD** (*PostScript Printer Description*) | Model yetenekleri ve seçenekler; CUPS’ın yazıcıyla nasıl konuşacağını bilir |
| **PostScript** | Sayfanın nasıl çizileceğini tarif eden sayfa tanımlama dili |
| `/var/log/cups/` | Erişim (*access log*) ve hata (*error log*) |

```bash
ls /var/log/cups/
```

## Komut satırı ile yazıcı ekleme

Web dışında LPIC-1’de sık kullanılan yol **`lpadmin`**:

```bash
lpinfo -m | grep -i "hp"
lpinfo -m | head
```

Örnek ekleme (adres ve PPD örnektir; gerçek sürücü `lpinfo -m` çıktısından seçilir):

```bash
sudo lpadmin -p my_printer -v socket://192.168.1.100 -E -m "foomatic-db-compressed-ppds:0/ppd/foomatic-ppd/Alps-MD-1000-md2k.ppd"
```

| Seçenek | Anlamı |
|---|---|
| `-p` | Yazıcı adı |
| `-v` | Bağlantı URI’si |
| `-E` | Etkinleştir |
| `-m` | Model / PPD |
| `-d` | Varsayılan yazıcı yap |

Sahte `model.ppd` verilirse sürücü hatası beklenen bir durumdur. Geçerli bir PPD seçilmelidir.

```bash
lpstat -p my_printer
sudo cupsaccept my_printer
sudo cupsenable my_printer
sudo lpadmin -d my_printer
lpstat -d
echo "CUPS test print" > test.txt
lp -d my_printer test.txt
```

`lp` modern CUPS istemcisidir; `lpr` ise BSD uyumluluk komutudur. İkisi de işi CUPS kuyruğuna iletir.

## Web arayüzü (port 631)

```text
http://localhost:631
```

| Menü | İş |
|---|---|
| Home | Genel görünüm |
| Administration | Sunucu ve yazıcı yönetimi; Add Printer |
| Classes | Sınıflar (bu derste işlenmez) |
| Help | Yardım |
| Jobs | Kuyruktaki işler |
| Printers | Yazıcılar / hedefler |

Yazıcı ekleme: **Add Printer** → sistem kullanıcısı / parola → yerel / keşfedilmiş ağ / diğer ağ → ad, açıklama, konum → model → onay. **Maintenance** ile test sayfası, duraklatma, iş reddi, taşıma, iptal yapılabilir.

Örnek iş akışı:

```bash
systemctl status cups
echo "CUPS test print" > test.txt
lp -d "my printer" test.txt
lpstat -o
```

Kullanıcı doğrudan yazıcıya konuşmaz. İş önce CUPS’a gider; CUPS job oluşturur, kuyruğa koyar, sonra cihaza göndermeyi dener.

## Legacy BSD araçları ve `cups-bsd`

MTA dersindeki Sendmail uyumluluğuna benzer: eski betikler `lpr`, `lpq`, `lprm`, `lpc` bekler. CUPS bunları **`cups-bsd`** paketiyle sağlar.

| Komut | Açılım | İş |
|---|---|---|
| `lpr` | line printer | İş gönderir |
| `lpq` | line printer queue | Kuyruğu listeler |
| `lprm` | line printer remove | İş siler |
| `lpc` | line printer control | Yazıcı durumunu / denetimini gösterir |

Gerçek **LPD** paketi kurulursa aynı isimli ama farklı (gerçek LPD) araçlar gelir. İstenen, CUPS’ın uyumluluk katmanıdır → **`cups-bsd`**.

### Deneme

```bash
echo "CUPS legacy tools test" > myfile
cat myfile
lpr myfile
```

Varsayılan yazıcı yoksa: `no default destination`. Yazıcıyı belirt:

```bash
lpr -P "my printer" myfile
lpq -P "my printer"
lpq -a
lprm -P "my printer" 8
```

Tüm işleri silmek:

```bash
lprm -P "my printer" -
```

Yetki yoksa `forbidden` gelebilir; root ile:

```bash
sudo lprm -P "my printer" -
```

### `lpc` ve iki anahtar

```bash
sudo lpc status
```

Çıktıda ayrı ayrı görülebilir:

- **queuing is enabled** — kuyruğa yeni iş kabul
- **printing is enabled** — kuyruktan cihaza gönderme

Bunlar birbirinden bağımsızdır.

---

## Kuyruğa kabul ≠ yazdırma

| Senaryo | Queuing | Printing | Amaç |
|---|---|---|---|
| Bakım (kâğıt bitti) | Açık | Kapalı | İşler birikir; yazdırma sonra devam eder |
| Mesai bitişi | Kapalı | Açık | Yeni iş yok; mevcut kuyruk eritilir |

Dört komut:

```bash
cupsreject "my printer"
cupsaccept "my printer"
cupsdisable "my printer" -r "needs more paper"
cupsenable "my printer"
```

| Komut | Ne yapar |
|---|---|
| `cupsaccept` | Yeni işleri kuyruğa kabul et |
| `cupsreject` | Yeni işleri reddet |
| `cupsenable` | Cihaza göndermeyi aç |
| `cupsdisable` | Cihaza göndermeyi kapat; `-r` ile neden mesajı |

Modern GUI varken bu komutlara az başvurulur; sınav için ayrım bilinmelidir.

## Özet

- CUPS ortak Unix yazdırma sistemidir; yapılandırır, kuyruklar, sorun giderir ve BSD legacy komutlarını destekler.
- Servis: `cupsd`. Kurulum `apt install cups`. Durum `systemctl status cups`, log `journalctl -u cups`.
- Yönetim: GUI, web (`localhost:631`), CLI. Dinleme ve yetki `cupsd.conf` içindedir.
- Yazıcı kaydı `printers.conf`; model bilgisi PPD; loglar `/var/log/cups/`.
- CLI ekleme: `lpinfo -m`, `lpadmin -p … -v … -E -m …`, `lpstat`, `cupsaccept` / `cupsenable`, `lp -d`.
- Legacy: `cups-bsd` ile `lpr` / `lpq` / `lprm` / `lpc`. Gerçek LPD paketi değildir.
- Queuing ve printing ayrıdır. `cupsaccept`/`cupsreject` kuyruğu, `cupsenable`/`cupsdisable` yazdırmayı kontrol eder.
