## Grafik Yığını (Büyük Resim)

```text
User
  ↑
GUI (Graphical User Interface)
  ↑
Window Manager  ·  Display Server
  ↑
Linux Kernel
  ↑
Hardware
```

- **Kernel** — hardware ile iletişim; üst yazılımların donanımı kullanmasını sağlar
- **Display Server** — uygulamaların görüntüsünü ekrana aktarmaya yardımcı olur
- **Window Manager** — pencerelerin yerleşimi, boyutu, odağı
- **GUI** — kullanıcının gördüğü grafik arayüz

Akış: kullanıcı en üstteki arayüzle etkileşir; alt katmanlar işlemleri hardware'e taşır.

## 106.1 — X11

**X11** (X Window System / X) — Linux/Unix'te GUI'yi yöneten display server protokolünün 11. ve yaygın sürümü.

### X Client / X Server modeli
| Rol | Ne yapar |
|---|---|
| **X Client** | Grafik uygulama (Firefox, terminal…). Pencere aç / çiz / girdi işle istekleri üretir |
| **X11** | Client ↔ Server iletişim protokolü / grafik sistem ailesi |
| **X Server** | Ekran + klavye/fare; çizim isteklerini yansıtır, girdiyi ilgili Client'a iletir |
| **Xorg** | Linux'ta X11'i uygulayan yaygın **X Server** yazılımı |

**Önemli:** “Server” mutlaka başka bir makine demek değildir — aynı makinedeki X Server da olabilir.

Client ve Server **aynı makinede olmak zorunda değildir**: uygulama uzak makinede çalışır, görüntü yerel X Server'da gösterilebilir (ağ özelliği; SSH X11 forwarding senaryolarında da görülür).

```text
Klavye/fare → X Server → olaylar X Client'a
X Client → çizim komutu → X Server → ekran güncellenir
```

### Display Server ≠ Display Manager ≠ Window Manager

| Bileşen | Görev | Örnek |
|---|---|---|
| **Display Server** | Görüntüleme + input yönetimi | Xorg |
| **Display Manager** | Login screen + desktop session başlatma | GDM, SDDM, LightDM |
| **Window Manager** | Pencere boyutu, konum, odak, decoration | (DE içinde gelir) |
| **Desktop Environment** | Panel, launcher, settings, file manager + WM… | GNOME, KDE, Xfce |

Window Manager ≠ Desktop Environment: WM sadece pencereleri yönetir; DE masaüstü deneyiminin tamamını sunar.

### Yapılandırma dosyaları
| Yol | Rol |
|---|---|
| `/etc/X11/xorg.conf` | Xorg yapılandırması (modern sistemlerde çoğu zaman gerekmez — otomatik algılama) |
| `/etc/X11/xorg.conf.d/` | Parça yapılandırma dosyaları |
| `~/.xsession-errors` | Kullanıcı X session hata/mesajları |

Ezber şart değil; hangi dosyanın ne işe yaradığını bilmek yeterli.

### DISPLAY, xhost, xauth
| Kavram | Rol |
|---|---|
| `DISPLAY` | Grafik uygulamanın hangi X Server'a bağlanacağını belirten **ortam değişkeni** (process değil) |
| `xhost` | Hangi istemcilerin X Server'a erişebileceğini kontrol eder (daha geniş erişim) |
| `xauth` | Authentication cookie ile erişim doğrular |

`xhost` ile erişimi herkese açmak **güvenli değildir**.

LPIC ipucu: **xhost** = erişim listesi · **xauth** = kimlik doğrulama.

### Wayland
| | X11 | Wayland |
|---|---|---|
| Model | X Client / X Server | Modern display protocol |
| Durum | Uzun süredir kullanılan, kapsamlı | Modern alternatif |

Birçok dağıtım/DE Wayland sunar; eski X11 uygulamaları için uyumluluk bileşenleri kalabilir. LPIC-1 için temel farkı bilmek yeter.

## 106.2 — Desktop Environment

DE = panel/toolbar, menü, bildirim, ağ/güç yönetimi, file manager, uygulamalar… — sadece pencere değil, bütün masaüstü ortamı.

| DE | Öne çıkan |
|---|---|
| **GNOME** | Sade, bütünleşik; productivity / accessibility odaklı |
| **KDE Plasma** | Yüksek özelleştirme (panel, theme, icon…) |
| **Xfce** | Hafif; kaynakları uygulamalara bırakır; modüler |

Ubuntu Desktop varsayılanı genelde **GNOME**; kullanıcı başka DE seçebilir.

LPIC için yeterli: üçü de **Linux Desktop Environment** örneğidir.

### Display Manager örnekleri
| DM | İlişki |
|---|---|
| **GDM** | GNOME Display Manager — GNOME ile yaygın |
| **SDDM** | Simple Desktop Display Manager — KDE Plasma ile yaygın |
| **LightDM** | Hafif; belirli bir DE'ye bağlı değil (Xfce vb. ile kullanılabilir) |

Görev aynı: login screen + başarılı girişte desktop session. Tasarım ve bütünleşme farklı.

Karşılaştırma (isteğe bağlı okuma): [Baeldung — Display Managers](https://www.baeldung.com/linux/display-managers-install-uninstall#bd-lightdm-lightweight-display-manager)

### Uzak grafik erişim protokolleri
| Protokol | Kısa eşleme |
|---|---|
| **XDMCP** | X Display Manager Control Protocol → X11 + Display Manager + uzak grafik oturumu (eski yaklaşım; modern genel remote desktop değil) |
| **VNC** | Virtual Network Computing → uzak ekranı görüntüleme ve kontrol |
| **SPICE** | Simple Protocol for Independent Computing Environments → özellikle **VM** grafik konsolu (KVM vb.); “VNC'nin başka adı” değil |
| **RDP** | Remote Desktop Protocol → remote desktop; Windows'ta yaygın; Linux'ta örn. **xrdp**; varsayılan port **TCP 3389** |

```text
XDMCP  →  X11 / Display Manager / uzak grafik oturumu
VNC    →  Uzak ekran
SPICE  →  Virtual machine grafik erişimi
RDP    →  Remote desktop (TCP 3389)
```

## 106.3 — Accessibility

Amaç: bilgisayarlar **herkes** tarafından kullanılabilir olmalı. Farklı fiziksel ihtiyaçlara (görme, işitme, hareket…) göre arayüz ve sistem uyarlanır — tek araç değil, birden fazla yaklaşım.

### 1. Görsel
Yüksek kontrast, büyük metin, büyük imleç, ekranı büyütme, animasyon azaltma, görsel uyarılar.

### 2. Screen Reader ve Braille
| Kavram | Rol |
|---|---|
| **Screen Reader** | Ekran bilgisini sesli aktarır |
| **TTS** | Text to Speech — metni sese çevirir |
| **Orca**, **emacspeak** | Linux Screen Reader örnekleri |
| **Braille display** | Metni dokunsal Braille hücreleriyle sunar |

### 3. Keyboard Accessibility
| Özellik | Ne yapar |
|---|---|
| **Repeat Keys** | Basılı tutulan tuşun tekrar davranışını düzenler |
| **Sticky Keys** | Kombinasyonları sırayla basarak girme |
| **Slow Keys** | Tuşun kabulü için gecikme |
| **Bounce Keys** | İstemeden tekrarlanan vuruşları filtreler |

### 4. Mouse ve ekran
| Özellik | Ne yapar |
|---|---|
| **Mouse Keys** | Klavye ile imleç kontrolü |
| **Hover / dwell click** | İmleci tutmak click tetikler |
| **Desktop Zoom** | Ekranın bir bölümünü büyütür (bazen imleci takip eder) |

### 5. Voice Recognition ve alternatif input
Ses → komut/metin; imleç farklı cihaz/yöntemle kontrol edilebilir. Amaç: tek standart input biçimine bağlı kalmamak.
