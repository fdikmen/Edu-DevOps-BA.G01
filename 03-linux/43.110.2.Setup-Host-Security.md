# LPIC-110.2 — Host güvenliği

## Konu

LPIC Topic **110** — Security. Bu ders **110.2**: host güvenliğini kurmak (*setup host security*).

| Kod | Konu | Ağırlık |
|---|---|:---:|
| **110.2** | Setup host security | 3 |

Kimlik değiştirme, `sudo` ve parola yaşı [110.1](42.110.1.Perform-Security-Administration-Tasks.md) içinde kaldı. Runlevel ve boot target [101.3](05.101.3_Part1_Runlevels_ve_Boot_Targets.md) içinde geçti. Burada sınır hostun kendisidir: parola özeti nerede durur, kabuk nasıl kapanır, gelen TCP’yi kim karşılar, işe yaramayan servis neden kalkar.

Ağırlık 3’tür. Konu dağınıktır; bir kısmı önceki derslerin tekrarındır, bir kısmı güncel dağıtımda artık çalışmayan araçlardır. Sınav yine de o araçların rolünü sorar. Üç çekirdek vardır: shadow dosyası, kullanılmayan ağ servisini kapatmak, TCP wrapper’ın işi.

| Müfredat | Derste karşılığı |
|---|---|
| Shadow parolaları | `/etc/passwd` içinde `x`, özet `/etc/shadow` |
| Kabuk ve genel giriş kilidi | `/usr/sbin/nologin`, `/etc/nologin`, `passwd -l` |
| TCP wrapper | `libwrap`, `/etc/hosts.allow`, `/etc/hosts.deny` |
| Süper sunucu | `inetd`, `xinetd`, `/etc/xinetd.d/` |
| Güncel karşılık | `systemd` socket unit |
| Kullanılmayan servis | `systemctl`, `chkconfig`, `update-rc.d` |

Sınav listesindeki dosyalar: `/etc/nologin`, `/etc/passwd`, `/etc/shadow`, `/etc/xinetd.d/`, `/etc/xinetd.conf`, `systemd.socket`, `/etc/inittab`, `/etc/init.d/`, `/etc/hosts.allow`, `/etc/hosts.deny`.

Ana hat: shadow → kabuk kilidi → `/etc/nologin` → port → süper sunucu → wrapper → socket unit → saldırı yüzeyi → servisi durdurmak.

## Parola nerede durur

Eski Unix parola bilgisini `/etc/passwd` içinde tutardı. Her süreç sayısal UID’yi ada çevirmek için bu dosyayı okur. Dosya bu yüzden dünyaca okunur kalmak zorundadır. Özet orada durunca sözlük ve kaba kuvvet denemesi herkesin eline geçer.

Yol üç basamaktır. Önce düz metin parola. Sonra tek yönlü özet, hâlâ `passwd` içinde. Sonra **shadow**: özet, root’un okuduğu dosyaya taşınır.

```text
cat /etc/passwd
cat /etc/shadow
```

| Dosya | İzin | Parola alanı |
|---|---|---|
| `/etc/passwd` | `-rw-r--r--`, herkes okur | Yer tutucu `x`. UID, ad, ev, kabuk burada |
| `/etc/shadow` | `-rw-r-----`, root | Tuzlu özet, süre ve yaşlandırma |

Normal hesap `cat /etc/passwd` ile bütün kayıtları görür. `cat /etc/shadow` izin hatası verir. Ayrıcalık [110.1](42.110.1.Perform-Security-Administration-Tasks.md) içindeki SUID’li `passwd` programı bu dosyayı kullanıcı adına günceller; kullanıcı dosyayı kendisi açmaz.

---

## Kabuğu kapatmak

Etkileşimli kabuğu kesmek hesabı bütünüyle kilitlemek değildir.

```text
sudo useradd -m testuser
sudo passwd testuser
grep testuser /etc/passwd
sudo usermod -s /usr/sbin/nologin testuser
```

Kabuk alanı `/bin/bash` veya `/bin/sh` iken kullanıcı oturum açar. `/usr/sbin/nologin` yazılınca giriş bu programı çalıştırır. Program mesaj basıp çıkar; etkileşimli kabuk oluşmaz. Birçok sistem hesabının kabuk alanı zaten budur.

Kabuk kapalıyken FTP, posta ve kabuksuz SSH tüneli sürebilir:

```text
ssh -N testuser@sunucu
```

`-N` uzak komut çalıştırmaz; tünel için bağlantı açık kalır. Gerçek kilit parola özetini geçersiz kılar:

```text
sudo passwd -l testuser
```

`passwd -l` kimlik doğrulamayı kilitler. Kabuk yolu ile hesap kilidi ayrı kollardır.

---

## /etc/nologin

Tek kullanıcının kabuğunu değiştirmek ile herkesin girişini kesmek ayrıdır. `/etc/nologin` normalde yoktur; bakım için oluşturulur.

```text
sudo vim /etc/nologin
```

Dosyanın içine bir mesaj yazılır. Giriş deneyen kullanıcı mesajı görür, bağlantı kapanır. Bu hem SSH hem yerel konsol için geçerlidir.

Satırları silmek yetmez. Dosya durduğu sürece giriş kapalı kalır. Açmak için dosyanın kendisi silinir.

| Mekanizma | Kimi keser |
|---|---|
| Kabuk `/usr/sbin/nologin` | Yalnız o hesapın etkileşimli kabuğu |
| `passwd -l` | O hesabın parola ile kimlik doğrulaması |
| `/etc/nologin` dosyası | Giriş deneyen herkes, dosya silinene kadar |

## Servis portu nasıl dinler

Ağ daemon’u bir taşıma katmanı portuna soket bağlar. Çekirdek, numaranın hangi aralıkta olduğuna göre yetki uygular.

| Aralık | Örnek | Kim bağlayabilir |
|---|---|---|
| Ayrıcalıklı, 1024 altı | 22 SSH, 80 HTTP, 443 HTTPS | root veya `CAP_NET_BIND_SERVICE` |
| Ayrıcalıksız, 1024–65535 | 4040 gibi | Yerel sıradan kullanıcı veya betik |

1024 altını root olmadan dinleyemezsin. 1024 ve üzerini herhangi bir yerel hesap açabilir. İstenmeyen bir betiğin yüksek portta dinlemesi bu yüzden mümkündür. Aktif dinleyici:

```text
ss -tuln
netstat -tlpn
lsof -i :port
```

Bu risk, “her program kendi portunu kendisi açsın” modelinin zayıf yeridir. Eski cevap süper sunucuydu: portları tek dağıtıcı kaydeder, gelen isteği arkadaki programa verir.

## inetd ve xinetd

**Süper sunucu** gelen TCP’yi karşılar, yapılandırmadaki programa teslim eder. 80 Apache’ye, 631 ilgili servise gider. 4040’ı dinlemek isteyen, bunu `xinetd`’ye işletmek zorundadır; o satırı çoğu zaman yönetici koyar.

İki gerekçe vardı. Güvenlik: bağlantıyı süper sunucu kabul eder, arkadaki sunucuyla o konuşur. Kaynak: 1 MB RAM’li makinelerde FTP, telnet, web ve gopher sürekli bellekte duramazdı. Servis istek gelince başlar, cevaplar, çıkar.

Bugün az sistem bu modeli çalıştırır. `systemd` kendi soket aktivasyonunu getirir. Sınav yine `inetd` / `xinetd` rolünü ve dosyalarını sorar. Ana dosya `/etc/xinetd.conf`, servis başına parçalar `/etc/xinetd.d/` altındadır.

Telnet örneği, alanların nasıl okunduğunu gösterir:

```text
service telnet
{
    disable         = no
    flags           = REUSE
    socket_type     = stream
    wait            = no
    user            = root
    server          = /usr/sbin/in.telnetd
    no_access       = 192.168.1.0/24
    access_times    = 09:00-16:00
}
```

| Alan | Anlamı |
|---|---|
| `disable = no` | Servis açık |
| `socket_type = stream` | TCP |
| `user` / `server` | Hangi kullanıcı, hangi program |
| `no_access` | Bu ağ reddedilir |
| `access_times` | Yalnız bu saat aralığı |

Saat ve ağ kuralını her servisin kendi dosyasına dağıtmak zordur. `xinetd` bunu servis dosyasında toplar. Telnet’in kendisi bu derste açılacak bir servis değildir; satırlar sözdizimi içindir.

## libwrap, hosts.allow, hosts.deny

Bağımsız daemon da **TCP wrapper** kullanabilir. Programa `libwrap` bağlanmışsa, TCP kabulünden önce iki dosyaya bakar.

```text
ldd /usr/sbin/vsftpd | grep libwrap
```

Çıktıda `libwrap.so` varsa desteği vardır. Yoksa `hosts.allow` o programa işlemez. Modern dağıtımlarda wrapper desteği çoğu zaman kaldırılmıştır; müfredat rolü durur.

| Dosya | Yazılınca |
|---|---|
| `/etc/hosts.allow` | Yalnız listelenen adresler o servis için izinli |
| `/etc/hosts.deny` | Listelenen adres reddedilir; eşleşmeyen serbest kalır |

İkisine birden kural yazılırsa önce `hosts.allow` okunur. Eşleşme varsa izin verilir. Allow’da yoksa `hosts.deny` bakılır. İkisinde de yoksa erişim açık kalır.

Alıştırma kendi laboratuvarındadır: `vsftpd` kur, FTP dene, önce deny satırıyla reddi gör, sonra allow satırıyla davranışın değiştiğini gör. Başkasının FTP’sine kural denemesi yapılmaz.

## systemd socket unit

Güncel karşılık `.socket` unit’idir. Init portu dinler, istek gelince eş `.service` unit’ini başlatır. Açılış kısalır, boşta duran servis bellek tutmaz. Servis çökünce yeniden başlayabilir; `systemd` gelen soketi tamponlar.

SSH üzerinde kendi makinede izlenen sıra:

```text
fuser 22/tcp -v
systemctl stop ssh.service
systemctl start ssh.socket
systemctl stop ssh.socket
systemctl start ssh.service
```

| Adım | Ne görülür |
|---|---|
| `fuser 22/tcp -v` | Portu tutan PID, çoğu zaman `sshd` |
| `systemctl stop ssh.service` | Servis portu bırakır |
| `systemctl start ssh.socket` | Portu PID 1, yani `systemd` tutar; bağlananı `sshd`’ye devreder |
| Geri alma | Socket durur, `ssh.service` yine kendisi dinler |

Servis adı dağıtıma göre `ssh` veya `sshd` olabilir. Deneme, kesilmesi sorun olmayan bir laboratuvar oturumunda yapılır; tek SSH oturumunu kesmek kapıda kalmak demektir.

## Saldırı yüzeyi

Kullanılmayan servis kalkar. “Her paket kurulu olsun” geniş yüzeydir: oyun, web, FTP, tarayıcı, her biri ayrı kapı. Dar yüzeyde tek iş vardır. Örnek: internet tek bir ön adrese gelir, oradan tek web sunucusuna gider. Eklenen her gereksiz servis yüzeyi büyütür. Eklenen kontrollü ön katman, dağınık servisin yerine geçer.

İhtiyaç yoksa servisi yalnız devre dışı bırakmak yetmez. Paketin kendisini kaldırmak daha dar bir yüzey bırakır.

---

## Neyin çalıştığını görmek

```text
sudo service --status-all
systemctl status
systemctl list-units --all --state=active --type=service,socket
```

| Komut | Ne listeler |
|---|---|
| `service --status-all` | Eski servis durum özeti |
| `systemctl status` | Unit durumu |
| `systemctl list-units --all --state=active --type=service,socket` | Aktif servis ve soket |

Kullanılmayan bir tarayıcı daemon’u listede görünüyorsa bağlantısı kesilir ve kaldırılır.

Açılıştan düşürmek dağıtıma göre değişir. İkisi de System V bağlantıları içindir; güncel unit `systemctl` ile yönetilir.

| Aile | Komut | Ne yapar |
|---|---|---|
| Red Hat | `sudo chkconfig vsftpd off` | Açılışta SysV servisini kapatır. Bağlar `/etc/rc.d/init.d` |
| Debian | `sudo update-rc.d vsftpd remove` | `/etc/rc*.d` başlatma sembolik bağlarını kaldırır |

## stop, disable, inittab

`systemctl` iki zamanı ayırır. `stop` süreci şimdi keser. `disable` bir sonraki açılışta başlatmaz. İkisi birlikte `--now` ile yazılır.

```text
sudo systemctl stop vsftpd
sudo systemctl disable vsftpd
sudo systemctl disable --now vsftpd
```

System V’de daemon’lar `/etc/init.d` betikleriyle çalışırdı. Runlevel bağları o betiklere işaret ederdi. Bugün çoğunu `systemctl` yönetir; betikler diskte duruyor olabilir ve sınav yolu hâlâ orasıdır.

`/etc/inittab` satırı dört alandır:

```text
id:runlevels:action:process
```

| Örnek / eylem | Anlamı |
|---|---|
| `id:3:initdefault:` | Varsayılan çok kullanıcılı runlevel 3 |
| `respawn` | Süreç ölürse o runlevel’da yeniden başlar |

Runlevel’dan target’a geçiş [101.3](05.101.3_Part1_Runlevels_ve_Boot_Targets.md) içindedir. Bu ders o dosyayı yeniden kurmaz; satırı tanımak yeter.

## Özet

- Ağırlık 3. Çekirdek shadow, kullanılmayan servis ve TCP wrapper’dır. Wrapper güncel dağıtımda çoğu zaman yoktur; rolü sınavda durur.
- `/etc/passwd` dünyaca okunur, parola alanı `x`’tir. Özet, tuz ve yaş `/etc/shadow` içindedir; normal `cat` izin hatası verir.
- `/usr/sbin/nologin` etkileşimli kabuğu keser. FTP, posta ve `ssh -N` sürebilir. Hesabı kilitlemek `passwd -l` işidir.
- `/etc/nologin` herkesin girişini keser. İçini boşaltmak yetmez; dosya silinir.
- 1024 altı port root veya `CAP_NET_BIND_SERVICE` ister. Üstünü yerel kullanıcı da dinleyebilir.
- `inetd` / `xinetd` portu kaydeder, isteği arkadaki programa verir, iş bitince süreci bırakabilir. Parçalar `/etc/xinetd.d/` altındadır.
- `ldd … | grep libwrap` desteği gösterir. Önce `hosts.allow`, sonra `hosts.deny`. İkisinde de yoksa erişim açık kalır.
- Güncel model `systemd` socket unit’tir. `ssh.socket` portu PID 1’de tutar.
- Kullanılmayan servis listelenir, `disable --now` ile kesilir, ihtiyaç yoksa kaldırılır. SysV için `chkconfig` veya `update-rc.d`. `inittab` satırı `id:runlevels:action:process` biçimindedir.

**Sıradaki:** 110.3 şifreleme ile veriyi koruma. Bu seride henüz yok.
