# LPIC-109.4 — Linux Commands Used in This Lesson

Bu ders istemci tarafı isim çözümlemesini kapsar: kayıt sorgusu, resolver dosyası, yerel `hosts`, NSS sırası ve `getent`. BIND / `named` kurulmaz. `/etc/resolv.conf` elle değişince NetworkManager veya `systemd-resolved` üzerine yazabilir.

## Komutlar ve yollar

| Komut / yol | Anlamı |
|---|---|
| `ping -c 1 linuxfirst.com` | Adı çözüp tek ICMP. IP çıktıda görünür; kayıt özeti değildir |
| `host linuxfirst.com` | A, AAAA ve varsa MX özeti |
| `host yahoo.com` | Aynı özet, başka alan adı |
| `host -t AAAA yahoo.com` | Yalnızca AAAA (IPv6) kayıtları |
| `host server` | DNS’e sorar. Yalnız `/etc/hosts` kaydıysa çoğu zaman bulunamaz |
| `dig yahoo.com` | Protokol seviyesi DNS cevabı |
| `dig @1.1.1.1 yahoo.com` | Belirli DNS sunucusuna sor. Port 53 |
| `dig server` | DNS’te yoksa NXDOMAIN / not found. `/etc/hosts` atlanır |
| `cat /etc/resolv.conf` | `nameserver` satırlarını okur |
| `sudo vim /etc/resolv.conf` | `nameserver` değiştirir. Kalıcılık garanti değildir |
| `cat /etc/hosts` | Yerel IP ↔ isim tablosu |
| `grep server /etc/hosts` | Yerel satırı süzer. Pratikte yaygındır |
| `cat /etc/nsswitch.conf` | `hosts:` ve diğer NSS sırası |
| `getent hosts server` | NSS `hosts` veritabanından getirir |
| `getent passwd kullanici` | Aynı fikir; `/etc/passwd` satırı |
| `/etc/resolv.conf` | İstemci DNS sunucu listesi |
| `/etc/hosts` | Bu makineye özel eşleme |
| `/etc/nsswitch.conf` | Çözümleme sırası |
| `systemd-resolved` | İstemci stub servisi. Farkındalık |
| `/etc/systemd/resolved.conf` | Üst DNS ayarı (dağıtıma göre) |

## Seçenekler, dosya satırları ve çıktı (bağımsız komut değildir)

| Bağlam | Öğe | Anlamı |
|---|---|---|
| DNS kayıt | A | IPv4 adresi |
| DNS kayıt | AAAA | IPv6 adresi |
| DNS kayıt | MX | E-posta yönü; öncelik değeri |
| DNS kayıt | TXT / CNAME / SOA | LPIC-1 kapsamı dışı |
| `host -t` | tür adı | Yalnız o kayıt türünü iste |
| `dig` | `opcode: QUERY` | Sorgu işlemi |
| `dig` | `status: NOERROR` | Temiz cevap |
| `dig` | `flags: qr` | Cevap bayrağı |
| `dig` | `ANSWER:` | Cevap sayısı |
| `dig` | TTL | Önbellek ömrü, saniye |
| `dig` | `Query time` | Sorgunun süresi |
| `dig` | `SERVER: …#53` | Sorulan DNS ve port |
| `dig @` | IP | `resolv.conf` yerine bu sunucu |
| `resolv.conf` | `nameserver` | Sorgunun gideceği sunucu; birden fazla olabilir |
| `resolv.conf` | `8.8.8.8` / `1.1.1.1` | Google / Cloudflare herkese açık DNS |
| `resolv.conf` | `127.0.0.53` | Yerel stub (`systemd-resolved`) |
| `hosts` | `IP` sonra ad(lar) | `192.168.1.50 mystorage server` |
| `nsswitch` | `hosts: files mdns4_minimal dns` | Önce dosya, sonra mDNS, en sonda DNS |
| `nsswitch` | `passwd: files` | Parola için `/etc/passwd` |
| `nsswitch` | `mdns4_minimal` | `.local` / Avahi tarafı |
| `nsswitch` | `dns` önde | Yerel ad bile ağa gider; önerilmez |
| `host` / `dig` | NXDOMAIN | DNS’te alan yok |
| `getent hosts` | NSS | Sıra `nsswitch`’e göre |
| `systemd-resolved` | `127.0.0.53:53` | Uygulamanın sorduğu stub |
| `systemd-resolved` | istemci kapsamı | Başka hostlara yetkili cevap vermez |

## Örnek akış

Yerel ad ekle, NSS ile oku, DNS araçlarıyla karşılaştır:

```text
# /etc/hosts örneği (yetkiyle düzenlenir):
# 192.168.1.50  mystorage server

ping -c 1 server
getent hosts server
host server
dig server
grep server /etc/hosts
```

`ping` ve `getent` yerel satırı görür. `host` / `dig` DNS’e gider; kayıt yoksa bulunamaz.

Belirli sunucuya sorgu:

```text
dig @1.1.1.1 yahoo.com
host -t AAAA yahoo.com
```
