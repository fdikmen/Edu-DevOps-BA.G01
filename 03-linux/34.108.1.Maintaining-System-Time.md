# LPIC-108.1 — Sistem Saatini Doğru Tutmak (Maintaining System Time)

## Konu
LPIC Topic **108** — Essential System Services. Bu ders **108.1**: sistem saati, donanım saati ve zaman senkronizasyonu.

| Kod | Konu | Ağırlık |
|---|---|:---:|
| **108.1** | Sistem saatini korumak | 3 |

Saat dilimi dosyaları [107.3](33.107.1-107.3.Administrative-Tasks-Users-Groups-Cron-Localisation.md) içinde kısaca geçmişti. Burada donanım saati, UTC ve NTP derinleşiyor.

Hedef: makinedeki saati doğru tutmak. Araçlar: `date`, `hwclock`, `timedatectl`, `ntpd`, `ntpdate`, `chrony`. Adres: **pool.ntp.org**.

---

## Donanım saati (RTC)

Bilgisayar açılınca saati anakarttaki **donanım saatinden** (RTC — Real-Time Clock) okur. Bu saat, makine kapalıyken ve prizden çekilmişken de anakart pilinden çalışır.

Pil bitmiş eski bir makine saati sorabilir; saat **1970**'e sıfırlanmış olabilir. Birçok sistemde 1970, zamanın başlangıcıdır. **Epoch time**, bu tarihten beri geçen saniye sayısıdır.

Donanım saati basit bir dijital saattir. Bir yıl içinde birkaç saniyelik sapma normaldir. Üzerinde saat dilimi bilgisi yoktur. Linux'ta bu saat genelde **UTC** olarak tutulur.

**UTC** (Coordinated Universal Time) — saat dilimlerinin referans aldığı evrensel zaman. Greenwich / Londra saati bu referansın gündelik adıdır.

---

## hwclock

Donanım saati `hwclock` ile okunur. Doğrudan donanımla konuştuğu için normal kullanıcı yetmez.

```bash
date
sudo hwclock
```

Sanal makinede (VirtualBox) Ubuntu sanal donanımda çalışır. `hwclock` fiziksel RTC'ye ulaşamayabilir:

```text
Cannot access the Hardware Clock via any known method.
```

Açılışta Linux, anakart saatini bir kez okuyup sistem saatine kopyalar. Makine açık kaldığı sürece `date` (yazılımsal saat) ile `hwclock` (donanım saati) birbirinden bağımsız ilerler. Sanal makinede işlemci yükü veya NTP/chrony yüzünden dakikalık fark görmek normaldir.

Aynı kopma fiziksel makinede de olur. macOS'ta hızlı bakış (ders demosu, LPIC komutu değil):

```bash
sysctl kern.boottime
date
```

## Açılışta saat

1. İşletim sistemi donanım saatini okur.
2. Bu değeri sistem saatine **UTC** olarak yazar.
3. `date` çalışınca sistem, UTC'ye saat dilimi farkını ekler ve yerel saati gösterir.

Örnek: UTC'den 8 saat ilerideysen donanım saati UTC'de kalır. İşletim sistemine "UTC+8" denir. Her `date` bu farkı ekler.

### Windows ile çift önyükleme

Eski Windows sürümleri donanım saatini **yerel saat** gibi kullanırdı. Windows 11 dahil güncel sürümlerde varsayılan hâlâ budur (geriye dönük uyumluluk). Windows yerel saati RTC'ye yazar; Linux aynı değeri UTC sanır. Sonuç, saat dilimi kadar kaymış bir saattir.

Windows kayıt defterinde **RealTimeIsUniversal** açılarak Windows'un da RTC'yi UTC okuması sağlanabilir. Sistemlerin çakışmaması için donanım saatini UTC'de tutmak en sorunsuz yoldur.

## Sistem saatini elle değiştirmek (`date -s`)

`date` hem gösterir hem ayarlar.

```bash
date -s "2022-01-15 10:30:00"
# date: cannot set date: Operation not permitted

sudo date -s "2022-01-15 10:30:00"
date
sudo hwclock
```

`date -s` yalnızca **sistem saatini** değiştirir. Donanım saati aynı kalır. Fiziksel makinede yeniden açılışta işletim sistemi zamanı yine RTC'den okuyabilir; sadece sistem saatini değiştirmek kalıcı olmayabilir. Kalıcı kılmak için sistem saati donanım saatine yazılır (`hwclock`, aşağıda).

Modern sistemde NTP/chrony açıksa saat kısa sürede yeniden düzelebilir.

Testi geri almak:

```bash
# en kolayı: VM'yi kapatıp açmak
sudo timedatectl set-ntp true
date
```

---

## Donanım saatini güncellemek

| Seçenek | Anlam |
|---|---|
| `--utc` | RTC'nin UTC tutulduğunu belirtir |
| `--localtime` | RTC'nin yerel saat tutulduğunu belirtir |
| `--systohc` / `-w` | Sistem saatini donanım saatine yazar |

`--utc` ve `--localtime` tek başına "şu anki saati RTC'ye yaz" demek değildir. Hangi standartta tutulduğunu söyler. Yazma işini `--systohc` (kısa: `-w`) yapar.

```bash
sudo hwclock --systohc --utc
# sudo hwclock -w
```

## Sistem, RTC biçimini nereden bilir?

```bash
timedatectl
```

`timedatectl` sistem tarihini, saatini ve saat dilimini gösterir ve yönetir.

**RTC in local TZ**

| Değer | Anlam |
|---|---|
| `no` | Donanım saati UTC |
| `yes` | Donanım saati yerel saat (localtime) |

Açılışta sistem RTC'yi okuyup sistem saatini ayarlar. Saat dilimi, bu UTC değerinin nasıl yerel saate çevrileceğini belirler (ör. `Europe/Istanbul`).

Bazı sistemlerde aynı bilgi `/etc/adjtime` son satırındadır: `UTC` veya `LOCAL`. Dosya her sistemde yoktur. Yokluğu tek başına hata değildir; durum `timedatectl` ile bakılır.

## Saat dilimi dosyaları

Dünya saat dilimlerine ayrılır. Ortak referans UTC'dir. Linux'ta RTC genelde UTC'dir; sistem, yapılandırılmış dilimi uygulayarak yerel saati gösterir. Dilim UTC+3 ise yerel saat UTC'den üç saat ileridedir.

### `/etc/timezone`

Ubuntu gibi bazı dağıtımlarda dilim adı düz metindir.

```bash
cat /etc/timezone
# Etc/UTC   veya   Europe/Istanbul
```

Varlığı dağıtıma göre değişir. Her Linux'ta asıl kaynak bu dosya değildir.

### `/etc/localtime`

Asıl işi bu dosya yapar. Çoğu sistemde `/usr/share/zoneinfo/` altındaki bir dosyaya **sembolik bağlantı**dır.

```bash
ls -l /etc/localtime
# /etc/localtime -> /usr/share/zoneinfo/Europe/Istanbul
```

İşaret edilen dosya ikili (binary) saat dilimi verisidir.

### zoneinfo

```bash
cd /usr/share/zoneinfo
ls
cd Asia
file Tehran
# time zone data
```

İçinde o bölgenin UTC farkı ve yaz saati kuralları vardır. `UTC` gibi bir bölgeye bağlı olmayan dosyalar da bulunur.

---

## Saat dilimini elle bağlamak

Zoneinfo dosyasını `/etc/localtime` olarak **kopyalamak** iyi fikir değildir. Tahran'da kural değişirse kopya güncellenmez. Her zaman sembolik link kullanılır. Link için tam yol gerekir.

```bash
sudo unlink /etc/localtime
date
# dilim dosyası yokken sistem UTC gösterir

sudo ln -s /usr/share/zoneinfo/Asia/Tehran /etc/localtime
ls -l /etc/localtime
date
# Tahran: UTC+3:30
```

Sistem saati doğruysa gösterilen yerel saat de doğrudur. Paket güncellemesi zoneinfo dosyasını değiştirirse link bunu otomatik görür.

Dersi kendi dilimine döndürmek:

```bash
sudo timedatectl set-timezone Europe/Istanbul
```

## NTP

GPS, kriptografi ve bilgi sistemleri tam zaman ister. Anakart saati buna yetmez.

**NTP** (Network Time Protocol) ağ üzerinden "saat kaç?" diye sorar ve cevabı alır. NTP sunucuları hassas saatlere ve atomik saatlere bağlıdır.

**pool.ntp.org** — en çok bilinen adres. Pool = havuz: çok sayıda sunucu. Bağlanınca havuzdaki bir sunucuya yönlendirilirsin. Birçok kurumun kendi NTP sunucusu vardır; onlar da başka NTP sunucularına bağlıdır.

---

## ntpd ve chrony

İkisi de NTP'yi uygular. Aralarında büyük bir işlev farkı yoktur; ikisini de bilmek gerekir.

| | **ntpd** | **chrony** |
|---|---|---|
| Konum | NTP'nin orijinal uygulaması | Daha yeni |
| Vurgu | Protokolün geniş özellikleri, güvenlik | Günlük kullanım; bağlanıp kopan makineler |
| Sunucu listesi | Yapılandırma + gerekirse keşif | Yapılandırma dosyası (yoksa elle yazılır) |
| Broadcast | Var | Yok (ihtiyacı yok) |

**Broadcast:** ağdaki tüm cihazlara aynı anda mesaj. `ntpd`, açılışta NTP adresi bilmiyorsa "saat kaç?" diye yayınlayabilir. Bir sunucu "ben NTP sunucusuyum" deyip sonraki sorguların kendisine gelmesini söyleyebilir.

`chrony` dizüstünde hangi sunucuların kullanılacağını dosyadan bilir.

---

## ntpdate

Sistem saatini bir NTP sunucusuyla **elle** eşitler. Yeni Ubuntu'da varsayılan kurulu gelmez. Eski bir araçtır; modern Ubuntu'da saat genelde `systemd-timesyncd` veya `chrony` ile gider.

```text
Command 'ntpdate' not found, but can be installed with:
```

```bash
sudo ntpdate pool.ntp.org
```

Komut zaman alır. Cevabı olduğu gibi saate yazmak olmaz: soru gidip cevap gelene kadar süre geçer. NTP bu yüzden sunucuya birçok kez sorar, gidiş-dönüş süresine bakar ve sapmayı hesaplar.

Yakın ve hızlı sunucuda birkaç ölçüm yeter. Gecikme saniyeler sürüyorsa daha çok örnek gerekir. Çıktı **offset** (sapma) söyler: saati şuna çekti, hata saniye olarak şuydu. Saat daha önce 2022'ye alınmışsa ilk offset büyüktür. Komut tekrarlanınca fark küçülür.

Sistem saati düzelince donanım saatini de buna göre yazmak gerekir (`hwclock --systohc`). Açılışta doğru saat buradan okunur. `ntpdate`'i ara sıra veya cron ile çalıştırmak mümkün; sürekli iş için servis vardır.

`ntpdate` ile `ntpd` aynı anda çalışmaz ve birlikte kurulmaz. İkisi de NTP soketini kullanır.

---

## ntpd

`ntpd`, sistem saatini NTP ile eşitleyen arka plan servisidir. Yapılandırma: `/etc/ntp.conf`.

Ana kısım **pool** satırlarıdır. Örnekte dağıtıma özel dört havuz ve `iburst` vardır:

```text
pool 0.debian.pool.ntp.org iburst
pool 1.debian.pool.ntp.org iburst
pool 2.debian.pool.ntp.org iburst
pool 3.debian.pool.ntp.org iburst
```

**iburst** — başlangıçta kısa aralıklarla birden fazla istek gönderir. Gidiş-dönüş farklarına bakıp istatistikle doğru zamanı hızla hesaplar.

NTP sunucusundan zaman alıp `ntpd` çalışıyorsan sen de başkalarına zaman söyleyebilirsin. İstenmezse "kimseye cevap verme" ayarı vardır. LPIC-1 için pool + `iburst` yeter; dosyanın geri kalanı günlük yönetimde çoğu zaman gerekmez.

### ntpq

`ntpq` sorgu aracıdır (`q` = query). Yeni Ubuntu'da olmayabilir:

```text
Command 'ntpq' not found, but can be installed with:
sudo apt install ntpsec
```

```bash
ntpq -p
```

Hangi NTP sunucularından zaman alındığını, her biri için **offset**, **delay** ve diğer alanları gösterir.

| İşaret | Anlam |
|---|---|
| `*` | Şu an kullanılan sunucu |
| `+` | İyi aday |
| `-` | Kötü; kullanılmayacak |

Günlük kullanımda birçok dağıtım `chrony`'ye geçmiştir. `ntpq` yine de sınavda bilinir.

---

## chrony

NTP'nin masaüstü ve dizüstü için uygun uygulamasıdır. Yapı `ntpd` ile aynı fikirdedir: havuzlar + `iburst`.

```bash
cat /etc/chrony/chrony.conf
```

Ubuntu yolu `/etc/chrony/chrony.conf`. Bazı dağıtımlarda dosya `/etc/chrony.conf` olur. Örnek adresler: `ntp.ubuntu.com`, `0.ubuntu.pool.ntp.org`. Dağıtımların kendilerine ayrılmış alt alan adları vardır.

| Dağıtım | Varsayılan |
|---|---|
| Red Hat (yeni sürümler) | chrony |
| Ubuntu (25.10 öncesi, tipik) | `systemd-timesyncd` |
| Ubuntu 25.10 ve sonrası | chrony (`systemd-timesyncd`'nin yerini aldı) |

```bash
systemctl status chrony
```

Servis çalışır ve seçtiği kaynağı gösterir. Saat elle çok ileri/geri alındıysa bir süre senkronize görünmeyebilir: fark büyüktür ve chrony saati zıplatmaz.

### Slewing

chrony sistem saatini bir anda ileri veya geri **sıçratmaz**. Saati yavaşça hızlandırıp yavaşlatarak doğruya yaklaştırır. Buna **slewing** denir.

Neden: fatura kesen bir sunucuda saat 2022'de kalsın, NTP "2023" desin ve saat bir yılda sıçrasın. Bir dakikalık konuşma bir yıllık süre gibi görünebilir. Zaman geri sıçrarsa servisler bozulabilir. `ntpd` de temkinlidir: açılışta saati düzeltebilir; fark çok büyükse sıçratmayı bırakır.

Bir saatlik fark için chrony bir saat zıplamaz; örneğin önümüzdeki 24 saatte farkı eritir. Zamanın geri gitmesi gereken durumda da saati geri sarmak yerine yavaşlatan bir algoritması vardır. Zaman ileri akar; düzeltme yavaş yapılır.

### Leap second

**Leap second** — Dünya'nın dönüşündeki düzensizliği dengelemek için UTC'ye zaman zaman eklenen 1 saniye.

chrony bu saniyeyi zıplatmaz. Günün son dakikasına yayar: 60 saniye saymak yerine o dakikayı 61 saniyede sayar. Her milisaniye biraz uzar. Pratikte sıçrama hissedilmez.

---

## chronyc

`chronyc`, chrony servisine bağlanan komut satırı arayüzüdür.

```bash
chronyc tracking
chronyc activity
chronyc sources
```

| Komut | Ne gösterir |
|---|---|
| `tracking` | Senkron durumu ve sapma (drift). **leap status**: normal mi, yavaşlıyor mu, hızlanıyor mu |
| `activity` | Etkinlik: kaynaklar iyi mi |
| `sources` | Kullanılan kaynaklar. Mantık `ntpq -p` ile aynı: seçilen, iyi ve kötü işaretlenir |

`chronyc` TCP ile uzak bir chrony'ye bağlanıp `activity` gibi **izleme** komutlarını çalıştırabilir. Uzaktan değişiklik yapılmaz.

```bash
chronyc -h uzak-sunucu activity
```

## Özet
- RTC pil ile kapalıyken de gider; Linux'ta UTC tutulur. `sudo hwclock` okur. VM'de RTC hatası normal olabilir.
- Açılışta RTC → sistem saati (UTC). `date` dilim farkını ekler. Windows varsayılanı yerel saattir; çift önyüklemede kayma olur.
- `date -s` yalnızca sistem saatini değiştirir. RTC'ye yazmak: `sudo hwclock --systohc --utc` (`-w`).
- Biçim: `timedatectl` → RTC in local TZ (`no` = UTC). Yedek: `/etc/adjtime` son satır.
- Dilim: `/etc/localtime` → `/usr/share/zoneinfo/...`. Kopya değil, tam yollu symlink. `/etc/timezone` her dağıtımda yoktur.
- NTP: **pool.ntp.org**. `ntpdate` elle ve eski; `ntpd` orijinal servis (`/etc/ntp.conf`, `iburst`, `ntpq -p`). İkisi aynı anda olmaz.
- chrony günlük kullanımdır (`/etc/chrony/chrony.conf` veya `/etc/chrony.conf`). Saati zıplatmaz (slewing). Leap second'u son dakikaya yayar.
- `chronyc tracking` / `activity` / `sources`. Uzaktan yalnız izleme.
